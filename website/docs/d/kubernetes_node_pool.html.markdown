# Data Source: nscale_kubernetes_node_pool

Reads a Nscale Kubernetes Service (NKS) node pool by ID.

Use this to reference a node pool that Terraform does not manage, or to read the observed replica counts of one that it
does.

-> **The NKS endpoint must be configured.** Set `nks_service_api_endpoint` on the provider, or the
`NSCALE_NKS_SERVICE_API_ENDPOINT` environment variable, before using this data source.

## Example Usage

```hcl
data "nscale_kubernetes_node_pool" "workers" {
  id = "7f3a9c1e-4b2d-4e8a-9c05-1d6b8e0f2a34"
}

output "ready" {
  value = data.nscale_kubernetes_node_pool.workers.ready_replicas
}
```

## Notes

* Lookup is by `id` only. The NKS list API filters names exactly and case-sensitively, and pool names are not unique
  across clusters, so name-based lookup would be ambiguous.
* `replicas` is the desired count and comes from the pool's spec. `current_replicas`, `ready_replicas` and
  `up_to_date_replicas` are observed, and differ from it while a scale or a roll is in progress. Reading them is the
  way to watch a roll from outside the apply that started it — `up_to_date_replicas` climbs as workers are replaced.
* `health_status` is `healthy` only once the pool has fully settled. For a compute pool that means the rollout is
  complete and all three counts equal `replicas`. For a reservation pool it is a coarser signal, decided on
  ready-versus-desired counts alone.
* The platform release attributes describe the pool's own release, which is reported separately from the cluster's.
* See the [`nscale_kubernetes_node_pool` resource](../r/kubernetes_node_pool.html) for the capacity modes, which fields
  are immutable in each mode, and how a `taints` or `labels` edit rolls a compute pool.
