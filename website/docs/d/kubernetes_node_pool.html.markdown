# Data Source: nscale_kubernetes_node_pool

Reads an existing NKS node pool by ID, for referencing a pool created elsewhere — by hand, by another Terraform
workspace, or by the console.

-> **Lookup is by ID only.** The API's list filter on display name is exact, case-sensitive and explicitly
non-unique — pool names are unique only within a cluster, so a name could not resolve to one pool without also taking
a cluster. Use [`nscale_kubernetes_node_pool`](../r/kubernetes_node_pool.html) to manage a pool you own.

-> **The NKS endpoint must be configured.** Set `nks_service_api_endpoint` on the provider, or the
`NSCALE_NKS_SERVICE_API_ENDPOINT` environment variable, before using this data source.

## Example Usage

```hcl
data "nscale_kubernetes_node_pool" "workers" {
  id = "XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX"
}

# Follow a roll, or check a pool is actually carrying work: up_to_date_replicas
# sits below replicas while workers are being replaced.
output "workers_ready" {
  value = "${data.nscale_kubernetes_node_pool.workers.ready_replicas}/${data.nscale_kubernetes_node_pool.workers.replicas}"
}

# The cluster the pool belongs to, should you need the rest of its configuration.
data "nscale_kubernetes_cluster" "main" {
  id = data.nscale_kubernetes_node_pool.workers.cluster_id
}
```

## Notes

* Exactly one of `compute` and `reservation` is ever set, decided by `provisioning_mode`. The other is null.
* `placement_id` is null on a compute pool: only a reservation-backed pool creates a placement.
* A node pool has no platform release of its own. The three `platform_release_*` attributes and
  `applied_platform_release_id` report the release it inherited from its cluster.
* Reading a pool mid-flight is expected to show `up_to_date_replicas` below `replicas` — that is a roll in progress,
  not an error. See [Rolling a pool](../r/kubernetes_node_pool.html#rolling-a-pool).
