# Data Source: nscale_kubernetes_cluster

Reads a Nscale Kubernetes Service (NKS) cluster by ID.

Use this to reference a cluster that Terraform does not manage — for example, to point the `kubernetes` provider at a
cluster created by the `nscale` CLI or another workspace.

-> **The NKS endpoint must be configured.** NKS has no default endpoint baked into the provider yet. Set
`nks_service_api_endpoint` on the provider, or the `NSCALE_NKS_SERVICE_API_ENDPOINT` environment variable, before
using this data source.

## Example Usage

```hcl
data "nscale_kubernetes_cluster" "existing" {
  id = "b2c8d4e6-1a3f-4c7b-9e2d-5f8a0c1b3d7e"
}

output "api_endpoint" {
  value = format(
    "https://%s:%s",
    data.nscale_kubernetes_cluster.existing.api_server_endpoint.private_host,
    data.nscale_kubernetes_cluster.existing.api_server_endpoint.private_port,
  )
}
```

## Notes

* Lookup is by `id` only. The NKS list API filters names exactly and case-sensitively, and display names are not
  unique, so name-based lookup would be ambiguous.
* `api_server_endpoint` is null until the cluster's control plane is reachable. Reading a cluster that is still
  provisioning returns null for it, and for `kubernetes_version_*` and the platform-release status attributes.
* `certificate_authority_data` is the cluster's public CA bundle, not a secret.
* See the [`nscale_kubernetes_cluster` resource](../r/kubernetes_cluster.html) for how to hand these values to the
  `kubernetes` and `helm` providers.
