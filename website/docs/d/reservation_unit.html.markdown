# Data Source: nscale_reservation_unit

Retrieves the accelerator capacity offering — the *reservation unit* — available to your organization for a given
accelerator and reservation granularity in a region.

A reservation unit is the platform-side capacity shape that a [`nscale_reservation`](../r/reservation.html) is claimed
from. Reading it lets a [`nscale_placement`](../r/placement.html) size its `host_count` from the unit's own topology
instead of hardcoding a host count.

Capacity is calculated within your organization's active allocation scope, so this data source only reports regions your
organization holds an allocation in, and the figures reflect what is actually reservable by you.

~> **`largest_contiguous_unit_count` is a snapshot.** It describes capacity shared with every other consumer in the
organization, read at the time of the last refresh. Another consumer can claim the last contiguous block between your
plan and your apply, so treat it as advisory — useful for failing fast and for reporting, but never a guarantee that a
reservation will succeed.

## Example Usage

Size a placement from the unit's topology rather than a magic number:

```hcl
data "nscale_reservation_unit" "training" {
  accelerator = "GB300"
  unit        = "NVL72"
}

resource "nscale_reservation" "training" {
  name        = "gb300-nvl72"
  accelerator = data.nscale_reservation_unit.training.accelerator
  unit        = data.nscale_reservation_unit.training.unit
  unit_count  = 2
}

resource "nscale_placement" "workers" {
  name           = "training-workers"
  reservation_id = nscale_reservation.training.id
  network_id     = nscale_network.training.id

  # An NVL72 unit spans 18 hosts, so two units is 36 — read from the API rather
  # than written down here.
  host_count = (
    nscale_reservation.training.claimed_unit_count *
    data.nscale_reservation_unit.training.hosts_per_unit
  )

  constraints = {
    policy = "pack"
  }

  server_spec = {
    image_id = var.image_id
  }
}
```

Fail during plan instead of hitting a `507 Insufficient Capacity` during apply:

```hcl
resource "nscale_reservation" "training" {
  name        = "gb300-nvl72"
  accelerator = "GB300"
  unit        = "NVL72"
  unit_count  = var.unit_count

  lifecycle {
    precondition {
      condition = var.unit_count <= data.nscale_reservation_unit.training.largest_contiguous_unit_count
      error_message = format(
        "Requested %d contiguous units but the largest block currently available is %d.",
        var.unit_count,
        data.nscale_reservation_unit.training.largest_contiguous_unit_count,
      )
    }
  }
}
```

## Schema

### Required

- `accelerator` (String) The public accelerator model or family to look up, for example GB300.
- `unit` (String) The public reservation granularity to look up, for example NVL72.

### Optional

- `region_id` (String) The identifier of the region to look the unit up in. If not specified, this defaults to the region ID configured in the provider.

### Read-Only

- `hosts_per_unit` (Number) The number of hosts claimed by one reservation unit. Multiply by a reservation's `claimed_unit_count` to size a placement's `host_count`.
- `id` (String) A synthetic identifier for the reservation unit, formed as `<region_id>/<accelerator>/<unit>`. The API issues no identifier for a reservation unit, since it is a regional offering rather than an owned resource.
- `largest_contiguous_unit_count` (Number) The largest contiguous reservation-unit count currently satisfiable, which is the effective upper bound on a new reservation's `unit_count`. This reflects capacity shared with every other consumer in the organization, so it can change between a plan and an apply — treat it as advisory rather than a guarantee.
- `machine_flavor_id` (String) The identifier of the Region machine flavor resolved for this reservation unit.
